IR@SABAH: One App, Four Platforms

A patient-education platform for Dr. Chandran Nadarajan, Consultant Clinical & Interventional Radiologist — Sabah, Malaysia.

Live at drchandranir.infoPrepared by Ravi

The brief

Dr. Chandran Nadarajan needed more than a brochure website. As an interventional radiologist, much of his work involves explaining minimally invasive procedures — thyroid ablation, uterine fibroid embolization, and similar treatments — to patients who are often anxious and unfamiliar with the terminology. The goal was a platform that could do four jobs at once: greet patients on a tablet in the clinic waiting room, run unattended on a dedicated front-desk kiosk PC, travel with them on their phone afterward, and stand on its own as a full clinic website for anyone searching for the practice online.

Rather than building four separate products, the brief called for one.

Two deliverables in one project

This project handed Dr. Chandran two things, not one:

01 · THE APP

One build, four platforms

A tablet kiosk, a dedicated Windows kiosk PC app, a mobile site and a full desktop website — all from a single responsive codebase, deployed everywhere at once.

02 · THE CMS

Your own content system

A password-protected admin panel at /admin lets Dr. Chandran’s team edit every page themselves — no developer, no redeploy, live instantly across all four platforms.

The approach: one build, four platforms

IR@SABAH (rebranded from an earlier working name, MediTouch) is built as a single progressive web app — one codebase of HTML, CSS and JavaScript, with no separate native app for each platform. The same responsive design adapts itself to wherever it’s opened:

On a tablet, mounted in the clinic, it opens as a branded kiosk screen: a full-bleed splash with the practice’s gold-and-navy identity, Dr. Chandran’s photo, and a single “Enter” button — designed to be glanced at and tapped by a patient sitting in a waiting room, not scrolled through like a typical website.

As a dedicated Windows kiosk app, that same kiosk screen is packaged with Electron into a standalone application for a front-desk PC — fullscreen with no taskbar, an idle screensaver that brings back the splash after a period of inactivity, and a password-protected exit, so the machine can be left running unattended without a patient (or a curious visitor) accidentally leaving the app.

On a phone, the same app becomes a compact patient companion: a language switcher up top, the doctor’s profile and experience front and center, and a bottom navigation bar for conditions, treatments, videos and testimonials — the kind of layout patients expect from an app, not a desktop site squeezed onto a small screen.

On a desktop browser, it opens out into a full clinic website: a persistent sidebar for navigation, a larger hero section, and room to browse the complete library of conditions and treatments — built for the visitor doing more careful research before a first appointment.

Because it’s one PWA rather than four separate builds, a content change — a new treatment, an updated bio, a corrected clinic hour — is written once and appears correctly on all four at the same time. There’s no “update the app, then remember to update the website too.”

What’s running underneath

The visible experience is only part of the story. A few things happen behind the scenes that a typical static clinic website doesn’t do:

An owner-editable CMS. All nine content sections — doctor bio, conditions, treatments, videos, education, testimonials and more — are managed from a browser-based admin panel at /admin, backed by a managed backend-as-a-service database. Dr. Chandran’s team can update content directly, without ever touching code or waiting on a developer.

Multi-user admin access. Rather than one shared password, the admin panel supports individual staff logins with per-section permissions — so someone managing testimonials doesn’t need the ability to edit treatment protocols, and vice versa.

A trilingual experience, properly done. English, Bahasa Malaysia and Chinese aren’t just menu labels — every page of content is authored in all three languages and switches instantly, without a page reload.

A patient-facing FAQ chatbot. A chat widget answers common questions drawn from the site’s own content. When it doesn’t know the answer, it offers the patient two paths: leave a name, phone number and reason for a callback, or jump straight to the clinic’s WhatsApp with the question already pre-filled — meeting patients on the channel they already use.

One-tap appointment booking. Every “Book Appointment” and enquiry button opens WhatsApp directly to the clinic’s number with a ready-written message, removing the friction of a contact form nobody wants to fill in from a waiting room.

A real production deployment. The site runs on a custom domain (drchandranir.info) with SSL, auto-deploying from Git through an on-demand serverless hosting platform — so every update to the codebase goes live without manual server work.

Why one build instead of four

The obvious alternative — a native tablet app, a separate kiosk-PC application, a native mobile app, and a separate website — would have meant four codebases to keep in sync, four places for a bug to hide, and four times the cost every time the clinic wanted to add a treatment or fix a typo. Building it once as a responsive PWA means:

  • One update ships everywhere at once.
  • One CMS controls every platform’s content.
  • New platforms (a second kiosk, a different tablet model) cost almost nothing to add — they’re just another screen size the same app already knows how to fill.

For a small clinic without an in-house IT team, that maintainability is arguably the more valuable engineering decision than any single feature on the page.

Tech stack

HTML / CSS / JavaScript (PWA, no build step) Backend-as-a-service database (auth + storage) On-demand serverless compute Git-based CI/CD to a serverless host Electron (Windows kiosk wrapper)
